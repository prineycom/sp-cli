# Integrating sp-cli into agents: MCP server + skill

Two artifacts, ready to plug into any agent:

- **MCP server** — `sp_cli/mcp_server.py` (wrapper `./sp-mcp`). Stdio JSON-RPC,
  MCP protocol `2025-06-18`, pure stdlib. Tools are generated by introspecting
  the CLI's argparse parser, so coverage is always 1:1 with every `sp` command
  (currently 97), including future ones.
- **Skill** — `integrations/skill/superproductivity/SKILL.md`
  ([Agent Skills](https://agentskills.io) format: `name`/`description`
  frontmatter + instructions). Teaches an agent the working techniques:
  id prefixes, `json=true`, short syntax, `yes=true` for destructive
  operations, recipes.

## Requirements

A configured sp-cli (`sp init --url ... --user ... --password ...`; the config
lives in `~/.config/sp-cli/config.toml` and can be overridden with the
`SP_CLI_CONFIG` env var). The server uses exactly the same write path as the
CLI: the op-log, vectorClock, backups, and conflict retry are inherited
automatically.

## Authentication

The MCP client config carries **no WebDAV credentials, and none are needed**:
the server executes the same code as the CLI, which reads
`~/.config/sp-cli/config.toml` and authenticates to the WebDAV server with
HTTP Basic auth on every request. Nothing writes to the file "around"
authorization, and duplicating the password into an agent's config would only
create one more copy of the secret.

To point one agent at a different Super Productivity setup (or a test copy),
give it its own config via the environment instead:

```json
{
  "mcpServers": {
    "superproductivity": {
      "command": "/path/to/sp-cli/sp-mcp",
      "env": { "SP_CLI_CONFIG": "/path/to/alternate-config.toml" }
    }
  }
}
```

## Registering the MCP server

The launch command is the same everywhere: `/absolute/path/to/sp-cli/sp-mcp`
(or `python3 -m sp_cli.mcp_server` with cwd at the repository root).

**Claude Code:**

```bash
claude mcp add superproductivity -- /path/to/sp-cli/sp-mcp
```

**Any client with an `mcpServers` config** (Cursor, VS Code, Claude Desktop,
Windsurf, ...):

```json
{
  "mcpServers": {
    "superproductivity": {
      "command": "/path/to/sp-cli/sp-mcp",
      "args": []
    }
  }
}
```

**Codex CLI** (`~/.codex/config.toml`):

```toml
[mcp_servers.superproductivity]
command = "/path/to/sp-cli/sp-mcp"
```

**Hermes Agent (Nous Research):**

```bash
hermes mcp add superproductivity --command /path/to/sp-cli/sp-mcp
# confirm tool enablement when prompted (Y = all 97 tools, or "select")
hermes mcp test superproductivity
```

Config equivalent in `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  superproductivity:
    command: /path/to/sp-cli/sp-mcp
    enabled: true
```

Use `/reload-mcp` in a running session (or start a new one) to pick up the
tools; `hermes mcp configure superproductivity` toggles individual tools;
`hermes mcp remove superproductivity` uninstalls.

**OpenClaw:** requires a release with the native `openclaw mcp` command
(check `openclaw mcp status`; older 2026.3.x builds predate it — run
`openclaw update` first).

```bash
openclaw mcp add superproductivity --command /path/to/sp-cli/sp-mcp
openclaw mcp doctor superproductivity --probe
```

Config equivalent in `~/.openclaw/openclaw.json`:

```json5
{ mcp: { servers: { superproductivity: {
    command: "/path/to/sp-cli/sp-mcp", transport: "stdio", enabled: true } } } }
```

Fallback for older OpenClaw builds without native MCP: use
[mcporter](https://github.com/steipete/mcporter) — from the agent workspace run
`npx mcporter config add superproductivity --stdio /path/to/sp-cli/sp-mcp`,
verify with `npx mcporter call superproductivity.sp_doctor`, and install the
mcporter skill (`npx clawhub install mcporter`) so the agent can call tools via
the mcporter CLI.

### Trimming the tool set

97 tools are a noticeable chunk of the client's context. If the agent only
needs part of the functionality, the set can be cut down with glob filters:

```bash
sp-mcp --read-only         # only listing/reporting tools; no writes possible
sp-mcp --exclude 'provider*' --exclude 'board*' --exclude 'counter*'
sp-mcp --include 'list' --include 'show' --include 'add' --include 'today*'
sp-mcp --list-tools        # inspect the resulting set without starting the server
```

The same filters can live in `~/.config/sp-cli/config.toml`, which is handy
when the agent's config format makes passing arguments awkward:

```toml
mcp_read_only = true                    # cannot be overridden by flags
mcp_include = ["list", "show", "today*"]
mcp_exclude = ["provider*", "init"]     # flags override include/exclude
```

**Choose the tool set for the trust level of the agent.** Destructive tools
require `yes=true`, but a model can and will pass it on its own — a
confirmation parameter is a speed bump, not a permission system. Field note:
the very first autonomous agent connected to the full tool set responded to
"do you have sp-cli tools now?" by systematically test-firing all 97 tools,
`sp_delete`/`sp_*_rm` included, with `yes=true` — and cleaned out live data.
For an autonomous bot (Telegram assistant, cron agent, small local model) use
`--read-only`, or at least `--exclude '*rm*' --exclude 'delete' --exclude
'bulk' --exclude 'archive' --exclude init`; give the full set only to
interactive sessions where a human reviews tool calls.

A sensible minimum for a "task assistant" agent: `--exclude 'provider*'
--exclude init` (an agent usually has no business reconfiguring the config or
calendars; `init` and `untrack` are marked with `destructiveHint` just in
case).

## Installing the skill

Copy (or symlink) the `integrations/skill/superproductivity/` directory into
the agent's skills directory:

- Claude Code (project): `.claude/skills/superproductivity/` — the symlink is
  already in place in this repository;
- Claude Code (global): `~/.claude/skills/superproductivity/`;
- other agents with Agent Skills support — their skills directory.

The skill does not depend on MCP: it describes both the `sp_*` tools and the
bare `sp` CLI, so it is also useful to an agent that has nothing but shell
access.

## Tool contract

- Name: `sp_<command>` with `_` instead of `-` (`sp board-panel-add` →
  `sp_board_panel_add`).
- The argument schema mirrors argparse: positionals are required,
  `store_true` — boolean, `append`/`nargs=+` — array, `choices` — enum,
  `type=int` — integer.
- The result is the command's text output; on a non-zero exit code — `isError`
  with stderr.
- Commands with interactive confirmation never read stdin (it is occupied by
  the protocol): without `yes=true` they return an error with a hint.
- `readOnlyHint`/`destructiveHint` annotations are set — clients can
  auto-allow reads and require confirmation for deletions.
