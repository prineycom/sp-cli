# sp-cli

CLI (Python 3.11+, stdlib + `requests`) for managing Super Productivity through
its WebDAV `sync-data.json` file, bypassing the app. Target: any WebDAV server
that a Super Productivity client (e.g. the Android app) syncs against.

## Commands

- Run: `python3 -m sp_cli ...` or `./sp` (wrapper); MCP server: `./sp-mcp`
- Tests: `python3 -m pytest tests/ -q`
- Unit tests never touch the network; integration tests only talk to loopback
  test servers. Never test writes against a live sync file by hand.

## Architecture

- `sp_cli/webdav.py` — GET/PUT of sync-data.json, `pf_2__` prefix, backups
- `sp_cli/model.py` — typed factories for SP entities (task/project/tag),
  defaults strictly as in the SP sources
- `sp_cli/ops.py` — operation log: recentOps, vectorClock, SP action codes
- `sp_cli/mutations.py` — pure state mutations (create/update/delete/plan/...)
- `sp_cli/cli.py` — argparse commands
- `sp_cli/mcp_server.py` — MCP stdio server: `sp_*` tools generated by
  introspecting `build_parser()`, executed via `cli.main(argv, rewrite=False)`
  in-process (wrapper `./sp-mcp`, skill in `integrations/skill/`)

## Critical invariants

- Every write operation must: increment the vectorClock for its clientId,
  append a correct op to `recentOps`, update `lastModified` and the top-level
  `clientId`. Otherwise other SP clients won't pick up the change or will
  conflict.
- The CLI's clientId is unique and never matches another SP client's.
- Before PUT — backup to `~/.local/share/sp-cli/backups/` (rotation of 10).
- Time is unix ms; dates are `YYYY-MM-DD` strings; ids are nanoid(21) as in SP.
- Format documentation: `docs/research-sync-engine.md`,
  `docs/research-data-model.md`, `docs/sp-plugin-contracts.md`.
